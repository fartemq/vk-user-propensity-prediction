# VK User Propensity Prediction

Машинное обучение для прогнозирования вероятности совершения пользователем целевого действия по обезличенным структурированным признакам.

Проект выполнен в рамках аналитического кейса VK и оформлен как end-to-end ML pipeline: от первичного анализа данных и построения baseline-моделей до ансамбля градиентного бустинга, кросс-валидации и генерации финального файла с предсказаниями.

---

## 1. О проекте

### Бизнес-задача

Вместо бинарного решения «совершит / не совершит» модель оценивает **скор — вероятность (propensity score)**, характеризующий склонность пользователя к целевому действию.

Такой подход позволяет ранжировать пользователей по вероятности отклика и потенциально использовать прогнозы для:

- приоритизации наиболее перспективных пользовательских сегментов;
- персонализации коммуникаций и продуктовых сценариев;
- более эффективного распределения маркетинговых ресурсов;
- оценки вероятности целевого действия на уровне отдельного пользователя.

> Целевое действие и семантика исходных анонимизированных признаков в проекте не раскрываются, поскольку задача основана на закрытом кейсе.

### Формальная постановка

Задача сформулирована как **бинарная классификация**.

Для каждого пользователя модель прогнозирует:

\[
P(y=1 \mid X)
\]

где `y = 1` означает совершение целевого действия.

Основная метрика — **ROC-AUC**, поскольку она позволяет оценивать качество ранжирования пользователей по predicted probability без выбора фиксированного порога классификации.

Общий pipeline выглядит следующим образом:


## 4. Этапы разработки

### 4.1. Подготовка данных

Из датасета отделяются:

- `target` — целевая переменная;
- `index` — технический идентификатор.

После удаления служебных колонок модель получает **1 360 признаков**.

Данные делятся на обучающую и валидационную части с сохранением пропорций классов:

```python
train_test_split(
    X,
    y,
    test_size=0.2,
    stratify=y,
    random_state=42
)
```

### 4.2. Baseline: Logistic Regression

В качестве первого ориентира используется логистическая регрессия с L1-регуляризацией:

```python
LogisticRegression(
    penalty='l1',
    solver='saga',
    max_iter=100,
    random_state=42,
    n_jobs=-1
)
```

Почему это полезно:

- позволяет проверить наличие линейно разделимой информации;
- L1-регуляризация подавляет часть шумовых и избыточных коэффициентов;
- создаёт интерпретируемый baseline, относительно которого можно оценивать дальнейшее усложнение модели.

Результат после увеличения числа итераций:

**ROC-AUC = 0.617509**

### 4.3. Decision Tree

Одиночное дерево используется как нелинейный baseline.

Результат:

**ROC-AUC = 0.583500**

Это показывает, что простого дерева недостаточно для эффективной работы на данном пространстве признаков.

### 4.4. Random Forest

Следующим этапом проверяется ансамблевый подход:

```python
RandomForestClassifier(
    n_estimators=300,
    max_depth=12,
    max_features=0.2,
    class_weight='balanced',
    n_jobs=-1,
    random_state=42
)
```

Результат:

**ROC-AUC = 0.6196**

Random Forest немного превосходит линейный baseline, однако остаётся слабее градиентного бустинга.

### 4.5. LightGBM

Для табличных данных основной нелинейной моделью стал LightGBM:

```python
LGBMClassifier(
    objective='binary',
    metric='auc',
    boosting_type='gbdt',
    learning_rate=0.05,
    n_estimators=1000,
    max_depth=6,
    num_leaves=31,
    feature_fraction=0.2,
    random_state=42,
    n_jobs=-1
)
```

Для контроля переобучения используется early stopping.

Результат на hold-out validation:

**ROC-AUC = 0.646121**

### 4.6. CatBoost

Дополнительно обучается CatBoost с ранней остановкой:

- `iterations=1500`
- `learning_rate=0.03`
- `depth=6`
- `eval_metric='AUC'`
- `rsm=0.2`
- `l2_leaf_reg=5`

Лучшая зафиксированная модель достигла:

**ROC-AUC ≈ 0.654202**

### 4.7. Ансамбль LightGBM + CatBoost

Чтобы проверить, дают ли разные алгоритмы комплементарные ошибки, вероятности моделей объединяются простым soft-voting/blending:

```python
final_blend_preds = 0.5 * preds_proba_simple + 0.5 * preds_cb
```

Результат:

**ROC-AUC = 0.657973**

Таким образом, blending дал прирост относительно одиночного LightGBM на hold-out validation.

---

## 5. Финальная валидация: 5-fold OOF

После первичного сравнения моделей финальная проверка проводится с помощью `StratifiedKFold` на **5 фолдах**.

Для каждого фолда:

1. формируется собственная train/validation часть;
2. обучается LightGBM;
3. включается early stopping;
4. сохраняются out-of-fold вероятности;
5. модель добавляется в ensemble.

После прохода всех фолдов рассчитывается единый OOF ROC-AUC.

### Итоговый результат

> **5-fold Stratified OOF ROC-AUC = 0.663567**

Это значение используется как основной показатель качества финального LightGBM ensemble в текущей версии проекта.

---

## 6. Сравнение моделей

| Модель | ROC-AUC | Роль в проекте |
|---|---:|---|
| Logistic Regression, L1 | **0.617509** | Линейный baseline |
| Decision Tree | **0.583500** | Нелинейный baseline |
| Random Forest | **0.6196** | Ансамблевый baseline |
| LightGBM | **0.646121** | Основная модель |
| CatBoost | **≈0.654202** | Альтернативный бустинг |
| LightGBM + CatBoost | **0.657973** | Hold-out ensemble |
| LightGBM, 5-fold OOF | **0.663567** | Финальная валидация |

### Что показали эксперименты

1. Линейная модель содержит полезный сигнал, но не полностью описывает структуру зависимости.
2. Одиночное дерево решений является слишком слабым базовым решением.
3. Random Forest даёт небольшой прирост, но уступает бустингам.
4. LightGBM значительно эффективнее классических baseline-моделей на этой задаче.
5. Blending LightGBM и CatBoost улучшает hold-out результат.
6. 5-fold OOF показывает более устойчивую оценку качества финального ensemble и даёт **0.663567 ROC-AUC**.

## 7. Генерация предсказаний

Для тестовой выборки:

1. загружаются признаки в той же структуре, что и train;
2. обрабатываются пропуски в числовых колонках;
3. применяется сохранённый scaler;
4. получаются вероятности от всех обученных LightGBM-моделей;
5. вероятности усредняются;
6. результат сохраняется в CSV.

Формат итогового файла:

```text
index,target
194357,0.128276
313222,0.450746
321873,0.544712
...
```

В предоставленном submission-файле находится **106 274** предсказания.

## 12. Ограничения текущей версии

Проект является сильным исследовательским ML-кейсом, но текущая версия ещё может быть улучшена.

### Что стоит доработать

**1. Feature engineering**

В текущем решении основной фокус находится на обучении моделей на исходном пространстве признаков. Следующим этапом можно исследовать:

- агрегаты и статистики по группам признаков;
- отношения и разности информативных признаков;
- признаки взаимодействий;
- устойчивое удаление высококоррелированных признаков;
- отбор признаков по permutation importance / SHAP.

**2. Более строгий pipeline preprocessing**

Стоит объединить preprocessing и модель в единый `sklearn Pipeline`, чтобы минимизировать риск несоответствия преобразований между train и inference.

**3. Настройка гиперпараметров**

Можно дополнительно оптимизировать:

- `num_leaves`;
- `max_depth`;
- `min_child_samples`;
- `learning_rate`;
- `reg_alpha` / `reg_lambda`;
- `subsample`;
- `colsample_bytree`.

Для этого разумно использовать Optuna.

**4. Более устойчивый ансамбль**

Вместо фиксированного веса `0.5 / 0.5` можно подобрать оптимальный blending на OOF-предсказаниях.

**5. Интерпретация модели**

Для полноценного аналитического проекта полезно добавить SHAP-анализ и исследовать, какие группы признаков сильнее всего влияют на propensity score.
